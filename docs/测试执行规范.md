# 测试执行规范

## 目标

测试应快速、确定、可隔离，并在失败时主动结束；不得因断言中止协程而长期占用Godot进程。

## 硬性规则

1. 日常施工只运行当前任务对应套件；阶段里程碑才运行`critical`全套。
2. 使用`tools/run_godot_tests.ps1`执行测试。每个场景独立进程，默认超时8秒；检测到断言或脚本错误后立即终止该进程及其子进程。
3. 测试必须自行建立所需地图、怪物、Boss、角色状态和固定数值，不得依赖游戏默认出生区域或其他测试留下的状态。
4. 公式测试使用固定输入、固定边界和纯函数；不得以随机一次命中、随机伤害或随机掉落作为通过条件。
5. 烟测只验证启动、数据、基础战斗和核心交互主链。Boss技能、选怪、装备、地图等复杂行为放在各自专测中，禁止重复覆盖造成互相干扰。
6. 需要验证随机系统时，验证概率公式、区间和确定性种子；不验证单次随机结果。
7. 每批修改只运行一次相关套件；失败后只重跑失败项，修复完成后再统一运行相关套件一次。
8. 普通任务不导出APK；里程碑才进行构建和适量真机验证。
9. 用户负责常规真机手动测试并反馈结果；Codex默认只生成APK，不主动连接手机。仅当Android专属性能、输入、权限或设备兼容问题无法通过桌面验证时，先说明专项测试目的，再请求连接手机。

## 常用命令

```powershell
.\tools\run_godot_tests.ps1 -Suite warrior -TimeoutSeconds 8
.\tools\run_godot_tests.ps1 -Suite bich -TimeoutSeconds 8
.\tools\run_godot_tests.ps1 -Suite critical -TimeoutSeconds 8
```

测试日志统一保存在工作区`outputs/test_logs`，失败后优先读取对应日志，不立即重复运行整套。
