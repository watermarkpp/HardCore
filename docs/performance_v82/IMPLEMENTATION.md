# v82 性能优化与验收依据

## 范围与生产路径

基线为已接受的 v81 集成提交 `643d4185cfb3c67f86c0821d5c2393ba0c1581e2`。本轮只处理 BGM 启动、群怪静态查询和技能动画资源复用，不改变游戏规则、数值、地图、掉率、UI 或输入节拍。范围冻结见 [SCOPE.md](SCOPE.md)，最终包和源码身份另见交付记录。

1. `CasterSkillAnimationPlayer._apply_frame` → `CasterSkillVisualRegistry.load_texture_path`：旧实现每次切帧请求资源，旧帧失去最后一个引用后不能由 ResourceLoader 的弱缓存继续保留。循环或补帧时重新解码相同 PNG，是实测热点。新增按精确资源路径保留的最近使用缓存，估算纹理空间最多 32 MiB、最多 512 项；不改变像素、帧顺序、帧事件、缩放、坐标和遮挡。淘汰只移除缓存引用，Sprite 正在使用的纹理仍有效。此界限约束额外缓存持有，不是整个游戏的总显存上限。
2. `EnemyActor._hc_tick_melee` → 安全区/WORLD 查询及邻格静态可走性：原同帧共享查询仍多次创建、哈希同一完整作用域，多个怪也重复测试相同不可变地形点。现在复用完整不可变作用域及局部字典引用；精确点静态结果只在同一物理帧、同一不可变地形身份、精确双精度半径和完整环境/地图/投影/安全区作用域中复用。每次仍核对权威字段；帧、地图代次、环境实例/版本、安全区所有者/版本、Callable、上下文身份或半径变化即重新绑定。可变地形、无版本环境提供者绕过新可走性缓存。活体障碍、敌我、距离、命中、伤害、攻击节奏、调度预算和实时狭相判断保持原实现。
3. 普通近战 `_hc_target_usable` 原本对玩家两次调用同一缓存安全区点查询，现在只做一次；特殊/远程怪保留原先额外的实时玩家安全区检查。没有扩大任何可攻击目标集合。
4. `TownMusicController._build_audio_nodes / _arm_delay` → `AudioStreamPlayer.play`：Godot 的 `play_basic` 会在播放边界创建 Vorbis playback，解析头部并分配解码器。新增 `PreparedMusicStream` 只提前创建原生解码器，不开始、不混音、不前进；播放仍交给原生 `AudioStreamPlaybackOggVorbis`。每次取用后清空准备槽，下一次入城可准备新实例。原 OGG、6 秒延时、70% 音量、Music 总线、切图/等待当前曲目结束和自然播放结束规则不变。

引擎依据：[Godot 4.7 播放入口](https://raw.githubusercontent.com/godotengine/godot/4.7-stable/scene/audio/audio_stream_player_internal.cpp)、[Godot 4.7 Vorbis 实现](https://raw.githubusercontent.com/godotengine/godot/4.7-stable/modules/vorbis/audio_stream_ogg_vorbis.cpp)。不是重写音频混音器。

## 最终代码的三轮 A/B

可复验命令：

```powershell
python tools/performance_v82/compare_runtime.py --prefix v82_final
python tools/performance_v82/collect_evidence.py
```

对比器串行替换且在 finally 中按原字节恢复两份性能源文件，不修改 Git 或数据。测试期间不能编辑这两份文件。脚本固定 v81 基线、怪物 ID 64、地图 1、种子 20260909、30 个真实 EnemyActor。每场预热 45 个物理帧，采样 320 个物理帧，双方均执行 9600 次怪物物理更新；初始位置逐项相等。未锁定的 process 回调比物理帧多，保留全部实际间隔，不强行截成 320 个。详细计时覆写关闭。

火墙场景为 6 片正式 FireWallFieldController、每片 3×3 格、共 54 个正式动画节点，使用规范 SnapshotV2、正式索引/精确相交/时序 claim 和真实非致命 `EnemyActor.take_damage`。每片至少 5 个 tick，确有伤害且无重复 claim。场景中伤害为 1、持续 60 秒，只是测试夹具输入，不写入游戏数据。

下表是三轮各项统计的中位数，单位毫秒。原始 12 份运行记录、完整逐帧间隔、演员数量/移动/攻击/实际伤害证明、源哈希见 [evidence/performance_summary.json](evidence/performance_summary.json) 及相邻 `rev07_v82_final_*.json`。

| 场景 | P95 基线 → 最终 | 每物理帧怪物 CPU 基线 → 最终 |
|---|---|---|
| 30 怪追击 | 14.335 → 14.427 | 6.472 → 6.241 |
| 30 怪近战 | 17.820 → 17.198 | 7.463 → 7.186 |
| 30 怪拥堵 | 17.916 → 16.757 | 7.430 → 7.018 |
| 30 怪 + 6 片火墙 | 18.979 → 17.728 | 7.691 → 7.136 |

追击 P95 相差约 +0.6%，视为基本持平，不能声称所有场景全部变快；近战、拥堵、AOE 的 P95 分别改善约 3.5%、6.5%、6.6%。单轮仍有桌面调度长尾，例如最终近战第二轮最大间隔 34.113 ms，原始记录未剔除。数据是 Windows headless CPU/回调间隔证据，包含调度和等待，不能换算成安卓/GPU FPS，也不证明所有停顿已经消失。

## 组件隔离证据

- 54 个正式火墙动画节点，360 次手动 0.1 秒更新：旧均值 86.391 ms，新均值 0.524 ms，首次配置约 38.339 → 15.092 ms。该压力夹具刻意制造同步循环/补帧，证明资源重载热点，不能当作正常游戏帧率。循环加载只有 6 次，缓存命中 48648 次，保留量约 253569 bytes。
- 音乐 Dummy 驱动组件中，普通播放边界后续约 0.39–0.48 ms，预备解码后的后续约 0.018–0.025 ms，首次准备路径实际播放约 0.208 ms。没有删掉解码工作，是把准备移至加载/重新入城准备阶段。不是手机听感验收。
- 测试比较 120×4096 个实际 PCM 样本，与原生普通播放逐样本完全一致且包含非静音；靠近曲尾输出、自然终止和再次从零开始一致。缓存测试保留所有逐帧事件、精确原纹理身份，验证内存/条目界限和淘汰后的正在显示纹理有效。

## 回归与中途问题分类

全部测试通过正式 console/headless runner，普通场景超时 30 秒、已知重场景最多 60 秒。测试索引收录分批结果；不能描述为一次完整 critical 全套通过。

- 静态查询：共享只读点、同帧环境版本/实例、地图代次、双半径、低于 float32 精度的半径差异、地形上下文替换/可变地形原位修改、安全区失效、特殊怪实时安全区和下一物理帧过期。
- 相邻怪物：追击路径、真实攻击 delivery、世界障碍、核心行为、safe projection、monster query preservation。
- 火墙正式 12 场景：每 tick 单次查询、每候选单次精确测试、视觉格纯展示、命中/时序 claim/边界/叠加/地图隔离/视觉生命周期/候选减少/无 group 扫描/规范快照身份。
- 共用视觉：动画路由、图像装配入口、投影/零几何、抗拒火环中心及精确怪物特效；音乐控制与实际场景生命周期。

发现并处理的中途问题：旧 M30 测试 damage 覆写少了 `ranged` 参数，补齐透传；初始缓存测试创建未配置怪而被正式生命周期清除，改用正式 setup；最初 AOE 夹具把相对格当绝对格，实际零命中，故 `v82_ab_aoe_*` 等早期结果只作展示诊断，不参与最终战斗收益。修正夹具后对最终代码完整重跑。自审发现新半径 Vector4 键的 float32 舍入风险，改用 float Variant 精确键并补行为测试；最终数据在该修复后取得。证据收集脚本首次误把物理帧数等同 process 回调数，按既有采样合同改为保留全部回调、并严格验证 9600 次物理更新；未修改生产或删减帧样本。

视觉回归两项在 v81 原代码同样失败：旧动画路由测试要求 100% 火焰高度，改为用户已接受的 60%；旧投影测试缺少 V2 绝对地图上下文和投影回调，补齐正式上下文并传给效果节点的严格校验，原多边形数量/中心/投射物仅诊断等断言全部保留。新增非零地图屏幕原点以防绝对坐标被当作位移。修夹具的第一轮漏传效果节点验证上下文仍失败，补齐后 PASS，未放宽生产校验。

`monster_exact_effects_test` 首次出现一次 Godot Dummy 纹理 RID 初始化错误，堆栈在未改动的 `MonsterVisual._load_client_texture` 同步测试加载路径；该测试不经过新增施法纹理缓存，正式怪物视觉采用原线程加载路径。v81 对照及最终代码复跑均 PASS，未改该测试或生产路径，原失败记录保留。这次复跑不能证明引擎瞬态问题已被修复。

## 冻结与限制

资源、数据、UI、地图、声音文件、技能范围/时间/伤害、掉落、存档和输入规则均无改动。版本 code 仅为同包覆盖安装递增到 82，版本名仍为 `hardcore 1.0 正式版`。保留用户 AGENTS.md、既存 68 个未跟踪文件和全部旧 APK/里程碑。具体冻结范围、包内与 v81 的逐项字节比较在交付证据中记录。

安卓设备/GPU、实机听感及持续长时间温控压力：NOT_RUN。当前无连接 ADB 设备；不能以桌面通过或 APK 导出成功替代这些结论。
