## 最高执行原则

本项目定位为私人离线刷装游戏：以传奇1.76的战斗节奏、刷装循环、地图探索、怪物生态和装备追求作为独立可追溯的**基准层**，在其上建立可长期扩展的玛法类单机框架。新装备、新属性、新套装、新Boss机制、新地图、新任务、新职业玩法和不同美术风格必须进入独立的**扩展层**，不得直接污染基准层。

后续施工优先级固定为：数据可追溯、玩法可扩展、资源可替换、系统可测试、内容可批量生产。每项任务必须标记所属层；跨层底层系统必须保持配置隔离、存档兼容和独立回归。本原则高于续表中所有历史阶段决策。

自2026-07-14起，资源研究采用“完整客户端先学习、需求查询后执行”的固定顺序。原始数据库分类和资源文件名不可信，只保留为来源；至少一个完整客户端必须逐容器、逐索引帧建立真实尺寸、偏移、像素摘要和哈希目录。任何装备、武器、头盔或人物外观都不得只在名称相符的分类内搜索。每次施工必须同步更新[施工记录](Construction_Log.md)、[项目总目录](Project_Master_Index.md)、专项资源目录和需要长期贯彻的总纲规则。

正式采用五层：`Vanilla Core → Expansion Layer → Rule Systems → Presentation / Art Skin → Runtime Services`。运行数据由ContentLayers按`Vanilla + 已启用Expansion + User Override`合并，玩法代码只消费Merged Game Database。详细规范与迁移状态见[五层架构规范与迁移表](Five_Layer_Architecture_Standard_and_Migration_Matrix.md)。

### 数据源优先级（总纲硬性规则）

1. **服务端数据优先用于规则与数值**：怪物属性、刷新、掉落、装备属性与要求、技能等级与消耗、商店、任务、地图连接等，优先采用已取得的1.76服务端数据。
2. **游戏客户端数据优先用于地图与表现**：MAP、WIL/WIX、角色与怪物动作、装备外观、技能特效、音效及界面资源，优先采用已取得的经典客户端数据。
3. **两端必须交叉核对**：名称、编号、地图代码、动作帧和功能定义不一致时，不静默覆盖；在结构化数据中保留服务端值、客户端值、采用值、来源路径、版本标签与可信度。
4. **服务端与客户端均缺失时才允许项目推导**：推导值必须标记为“项目推导/临时”，记录推导依据；不得标记为2003官服基准，也不得计入原版数据完整度。
5. **数据版本默认规则**：默认启用`2003官服1.76基准版`；幻境、圣域等归入`1.76后期追加内容`并由游戏设置开关控制，不混入基准版。
6. **施工与验收规则**：每个地图、怪物、Boss、装备、技能、掉落和任务条目，只有在来源标记、运行接入和回归验证均完成后，才计为正式完成。

### 测试资源控制规则（总纲硬性规则）

1. 后续任务统一使用`tools/run_godot_tests.ps1`的隔离测试链；断言/脚本错误立即终止，单项默认最多8秒，并清理该测试的子进程。
2. 日常施工仅运行当前任务相关套件，失败时只重跑失败项；修复完成后再统一运行相关套件一次，禁止无意义重复全量测试。
3. 公式与数值测试使用固定输入和边界；涉及随机时验证公式、范围或固定种子，不以单次随机结果判定通过。
4. 烟测仅覆盖稳定主链；Boss、选怪、装备、地图等由专用测试负责，避免重复验证造成误报和资源浪费。
