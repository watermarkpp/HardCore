# 手机覆盖升级自动迁移设计

目标：用户在手机覆盖安装同包名同签名新版，打开游戏即获得新格式存档。第三树施工，主树及独立审查固定提交不动。

PlayerState 是唯一业务所有者；新增 SaveUpgradeBackup 只管理原字节归档、哈希验证、升级完成标记。既有 JsonPersistenceService 仍是角色及仓库的正式写入者。启动界面在 GameData 等正式权威加载完成后调用 PlayerState 完成升级，失败复用现有重试/退出界面。非 headless 正式启动在 PlayerState._ready 先进入升级门禁，跳过此前自动写入的初始化；headless 的直接专项保留既有启动合同，升级专项显式调用同一公开门禁。

备份覆盖 profile_directory 全树、同账户根目录角色索引、旧单角色、仓库和 WAL 的全部同名副文件、gold_migrations 与音频/掉落偏好。不存在的根允许缺失；已存在但打不开、无法枚举、复制或哈希不一致即失败。不扫描日志、缓存、设备实验输出。原始清单发布之前只写备份目录；发布后备份不可改写，重新启动须验证该备份。完成标记绑定备份清单的哈希及目标升级合同。

只读预检使用现有实际业务验证器。合法旧备份可作为已知损坏主档的候选，但不会在预检时恢复；未来/未知主档禁止旧备份替代。检查索引、所有磁盘角色（包含孤儿）、旧单角色、仓库、WAL before/after、世界时钟和死亡事件、角色/仓库实例重复关系。任一失败时没有业务写入或角色公开。

预检通过后恢复既有 WAL，迁移旧单角色及旧共享仓库，逐角色经真实 select_character/load_save/save_game 正式完成身份及世界合同转换；同一进程无第二业务所有者。每档写入后检查正式文件仍可加载。所有角色成功且持久化队列结束后保存完成标记、清空活动角色，开放选择。写失败或中断保持门禁，原始归档仍在；重启重用已持久化的实例和已有幂等 journal/仓库账本。任何收据/journal 回收不在本任务范围。

验收：真实已归档 v90 手机存档（如现场存在）、v97 写入形状、旧名称技能与字符串装备、共享仓库/银行、世界死亡日志及物品事务记录；原字节备份、未来合同+合法旧备份整体只读、写失败后重试、完整标记损坏、备份损坏、空安装与重复启动。通过源码专项/相关回归后再做固定源 APK 门禁与实际手机验收，不将本地原生测试视为手机完成。
