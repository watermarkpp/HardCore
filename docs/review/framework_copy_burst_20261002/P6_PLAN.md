# P6 正式 AOE 死亡突发补证计划

> 单主控串行执行，复用 executing-plans 工作流；不创建子代理。

**Goal:** 证明真实释放形成的30个独立死亡任务同时在正式队列中存在，并通过原保存和资源路径排空、冷恢复。

**Architecture:** 测试继承既有自然场景的只读观测工具，但明确固定接收者以构造可重复队列边界。Root、Player释放、几何、HP、效果、死亡、奖励、writer和共享预算均使用正式实现，不直接创建Batch、不手塞队列、不强制同步pump。

**Tech Stack:** Godot 4.7 GDScript、既有隔离 APPDATA 原生 wrapper。

**Spec:** RFC v2第653行组合压力要求、29d/1d20报告中“死亡队列峰未达30”的开放边界。

## 约束与判据

- 只新增测试和报告；默认模块仍关闭；主树、第二树、真实存档均不触碰。
- 目标按既有身体半径排布，验证不重叠、正式地面合法。固定接收者仅属于明示测试边界，不声称自然移动性能。
- 正式创建角色、装备/技能/规则三来源，使用原冰咆哮时序/范围与非空容量票据。
- 第一释放形成指定30目标各3来源；原模拟钟完成360周期投递，90状态按原期限退休。
- 第二正式输入使用声明的高伤害初始属性，致死所有30目标。每次死亡信号后观察队列，保存达到30时完整身份/状态/帧号快照；不以总数替代峰值。
- 指定资源key的新线程任务、五张纹理结果、奖励/掉落/持久化排空、独立cold生产者绑定分别验证。
- 如两阶段未在同一tick发生，明确报告时间关系，不能声称RFC同时到期/致死边界已闭合。
- 仅共享预算真实服务，失败和超时保留。原神经/物理帧样本不能替代Android/GPU。
