# 群怪运行架构与定位结论

2026-10-08。施工基线 codex/integration，HEAD 215f0b2f651a51e6855ee813ddd99221690311a1；工作树有既有混合改动，实际运行内容以各 receipt 的源码指纹为准。手机基线见 BASELINE.md，本地最终对比见 LOCAL_COMPARISON.md。

## 已定位的成本

v106 手机末段34只怪、27只入战/移动、48个掉落，怪物 physics 约803.8 CPU ms/s。该计数为包含子段的累计耗时，不能相加，也不是GPU/FPS。保留原始失败采集和同窗口续采结果。

固定蜈蚣洞913203、34正式怪（30入战+4背景）、48真实掉落、38级法师、300物理tick的本地实验中，优化前包围选位重复检查大量最终不采用的候选；一项修补甚至使CPU高于v106。停用包围选位的归因实验显著降低成本；停用脚本motion-clear反而恶化真实物理挤压并少了有效移动者，属于FAIL，不能删除真实碰撞预判。所有停用实验只作归因，原字节恢复已留证。

## 用户最终行为合同

普通近战按八方向短段追击；远处向已观察的玩家方向走相邻段。合法攻击范围内站定攻击，冷却同样站定，玩家跑步按键、范围内移动和顶着怪物跑不触发站位重选。真正出攻击范围才追击。WORLD/frontline实际阻挡仍按正式攻击资格处理，不允许隔墙或身体阻挡假攻击。

2026-10-08 用户补充：普通近战提交时资格成立，该次攻击随后不因玩家跑远或新增空间阻挡撤销。提交记录冻结原目标、严格1GU准入投影、来源/目标生命周期及parent action；命中时仍走同一命中率、防御和HP结算链，去重只结算一次。来源或目标死亡、换图/代际/战斗epoch失效及安全区保护仍遵守正式生命周期边界。普通攻击表现使用完整authoring动作时长，由既有战斗动作时钟锁定身体；动画完成后才重新选目标、追击或开始下一次攻击，不新增Timer或伤害权威。

后排逐步绕行，站住后形成有效包围；不追求每帧最短路线、最优攻击站位或最快全员收敛。实际移动、动态身体碰撞、死亡、攻击许可和已提交伤害仍按每个真实物理tick处理。

用户最终统一伤害合同：只有真实飞行的投射物可通过飞行期间移动躲开，继续以实际接触结算。锁定法术保持锁定交付。全部瞬时AOE（包括极光电影式直线、触龙神124、赤月恶魔180、千年树妖195及明确启用的Boss特殊范围技能）按发动时位置确定目标并同步结算；表现延迟、warning清理和随后移动不再重新查询或追加HP。火墙每个正式跳点单独按当时区域做一次AOE，不改变寿命、跳点间隔和既有claim。旧直线延迟/移动躲避试验属于用户已替换的合同，保存在retired_line_motion_contract，不能作为当前验收。

## 当前职责与接线

- 原战斗动作时钟、source movement/attack许可、攻击提交/释放、HP和空间位置权威保持原所有者。入战不重置动作时钟。
- 首次取得有效目标的生产帧产生观察请求；观察沿既有约180–208ms间隔刷新，下一期限从实际服务时刻计算，不追赶补算过期批次。自然入战保留各自相位，不建立每怪Timer。该观察间隔仍使用现有单调墙钟；本轮未把全部AI期限迁成战斗时钟，不能声称已经完成这项额外时域迁移。
- decision_budget仅拥有弱引用、身份scope和入队年龄。共享真实physics epoch，每帧选最早等待的最多5个owner；批内按实际Node回调顺序执行，避免严格队头使一批退化为每帧一个。每owner每epoch最多poll一次、observation一次、blocked-neighbor一次；scope变更或同类重复留到下一epoch。
- 填充有限批次时剔除失效的队中请求，不让禁用/离树/旧scope占用等待轮次。保留FIFO原年龄；已服务的名额不退款。不每帧全扫整个等待队列。
- 入选批次是基本追击的有限服务义务，通过现有FrameBudget必要scope透明计费，包括overrun。不能与可选预取竞争后反复观察却永远拿不到绕行。5-owner上限是数量限制，不能宣称整个物理帧CPU严格小于1.2ms。一次邻居选择仍为既有有限八方向/接触逃逸枚举，不执行无界全图搜索。
- 已获source pursuit许可可在等待观察/绕行时保留；它只延续移动意图，不变成后续攻击许可。新target/map/life使其失效。世界revision改变立即撤销可见性，保留真实last-known调查点；昂贵LOS待轮次服务，避免旧可见性越过新障碍。
- 合法站定、直接步恢复、既有flank/route可继续时清除无用pending；死亡、离树和失去目标清理。取消不退还已服务份额，不删已承诺步或伤害。
- 普通近战正式循环取消target-relative站位chooser，使用既有相邻步、局部让路和地形绕路。旧chooser仍保留给明确消费者及非普通交付，不另建路线权威。
- 空间桶从4GU调为1GU，仍按最大正式footprint扩大查询、保留稳定combat顺序和实时窄相检查。新鲜目的地点用紧包围；带native recovery margin的接触绕行保持完整粗桶候选。不缓存可通行结果，不量化或改写角色实际坐标。

## 入战分布与范围

正式蜈蚣洞110/112/114/116/118的运行索敌规则是横纵各±5格矩形；闲置搜索原有280ms+17ms×相位错峰。普通爆裂/冰咆哮/火墙3×3；地狱雷光为半径2格、排除中心、最大24目标。范围不能单独证明同帧入战的绝对人数，也不能把24目标上限当成真实24命中。日常边移动边引怪以自然错峰为主；一次启用固定30怪的基准是压力负载，不代表常态入战分布。中央上限只避免少量到期重合拖累一帧。

## 验证边界

本轮采用新的站定/逐步包围合同。旧natural30场景的“全员径向缩短0.5GU且五个同时CLEAR”FAIL原样保留，没有降低旧断言或标成PASS。新settled场景复用相同30大尸王、正式碰撞和时钟，验证四个象限有真实攻击并持续60物理帧包围、前排不动、后排真实运动或有实时身体阻挡；不要求全部大体型同时获得理想内圈站位。旧五站位保证仍不是本轮已证明的能力。

全部失败阶段、unsafe候选和回退留在COMPARISON.json与各run目录。PC headless CPU下降支持同一手机热路径成本降低的推断，不能换算手机FPS；APK与本候选设备验收NOT_RUN。
