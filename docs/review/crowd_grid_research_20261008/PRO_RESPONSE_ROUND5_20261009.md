## 一、这会怎样改变当前架构判断

因此，前面使用的模型：

\[

仍可作为设计账本，但**不能把来自不同轨迹的耗时直接填进\(R\)、\(B\)，然后当作已经测得的达标条件**。其中的“宿主保留成本”“桥接增量”“native计算成本”，都需要对应明确、可比的执行范围。

## 三、数值错误说明：ABI可调用与算法等价必须分开验收

按你的回报，sampled PASS应保留为历史采样结果，但在fresh review发现问题后，**不能继续代表“当前数值合同已经通过”**。这里最重要的不是增加样本数量，而是先修正样本覆盖的合同和真实调用链。

### 1. `ra/rb`不能因为进入C++就改成`real_t`

Godot 4.7的GDScript标量`float`对应64位`double`；`Vector2`分量默认是32位，除非引擎采用双精度构建。两者不是同一个精度合同。:chatgpt-content-reference{index="1"}

固定源码中：

```text
r = maxf(0.0, ra + rb)
before = a.distance_squared_to(c)
after = b.distance_squared_to(c)
```

`ra/rb`参与的标量加法、`r*r`以及与`EPS`的运算，不能提前通过`real_t`参数或临时量降精度；而向量操作也不能全部换成双精度自写公式，声称“精度更高所以等价”。**应保留原来的标量精度、向量运算路径，以及二者之间原有的转换位置。**

这一原则同时适用于局部typed融合：GDScript里把原表达式改写成不同的向量/标量运算组合，也可能改变舍入位置，不能只审查C++函数签名。

### 2. “相切样本”必须区分几何相切与代码判定边界

`core_crossed()`实际有两条不同规则：

\[
\begin{aligned}
before < r^2:\quad&
(b-a)\cdot(a-c)<-EPS
\;\lor\;
after<before-EPS\\
否则:\quad&
\operatorname{dist}^2(q,c)<r^2-EPS
\end{aligned}
\]

当前`EPS`来自`GroundUnitSpace.EPSILON_GU`，值为`0.0001`。这里使用什么比较式，就应按什么比较式验证；**本轮移植不能顺手改成`EPS²`、`<=`或几何上的“距离小于半径”。**

因此，修正现有样本时，建议在原有证据中明确记录：

| 需要证明的内容 | 不能替代它的说法 |
|---|---|
| 实际输入经过Vector2存储后，是否真的几何相切 | 样本名字叫`tangent` |
| 是否进入`before < r*r`的起始重叠分支 | 只看终点有没有离开 |
| 非重叠分支中，实际距离平方位于`r*r-EPS`哪一侧 | 只在几何半径附近稍微加减一个数 |
| 真实ABI收到的`ra/rb`仍保留原double值 | C++内部用的是double，但入参此前已降精度 |

**几何相切样本和实现阈值两侧样本都应有明确身份，不能拿其中一个冒充另一个。** 也不能用放宽布尔断言、增大容差来接受改变了碰撞结果的实现。

### 3. “DLL绑定缺失”需要区分证据绑定和方法绑定

我没有看到你们本地修正内容，不擅自判断缺的是哪一层。闭环时应分别说明：

**二进制证据绑定：** 该次run实际加载的是哪个DLL，它与哪份源码、godot-cpp版本、引擎及构建配置对应。仅有构建目录中某个DLL的哈希，不能证明进程加载的就是它。

**Godot接口绑定：** 拟用生产入口是否确实通过注册后的扩展接口完成调用。官方文档明确区分类注册、`_bind_methods()`方法注册，以及`.gdextension`中的平台库路径配置；直接C++调用的通过不能替代这一整条路径的验证。:chatgpt-content-reference{index="5"}

如果缺的是run到DLL的证据关联，应记为相应证据未闭环，不要凭空宣称运行时方法未注册；反之，真实入口不可调用，也不能用内部函数测试通过来覆盖。

## 四、对主控的收紧结论

**不追加大范围重写，也不为这项更正重跑原full/frame_only对照。** 你正在进行的单批SDK修正，重点应是保住混合精度语义、纠正边界样本、补齐实际二进制与调用入口的证据。

随后对native quantum的判断，仍由**相同执行边界下实际可迁移的工作、宿主保留成本和接口成本**决定，而不是由14.386%、单个primitive的速度或sampled PASS决定。

**目前状态应表述为：观察开销直接归因`UNKNOWN`；ABI数值与绑定闭环尚待本批修正证明；当前quantum能否实现整段CPU降低50%仍无现有证据支持。** 这不否定继续研究，但不构成扩大迁移范围或接入主树的依据。
