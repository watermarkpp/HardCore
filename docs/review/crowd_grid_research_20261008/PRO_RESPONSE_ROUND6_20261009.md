## 一、先修正方案文档，避免下一项从错误边界开工

### 1. 方向保护必须在原索引发布之前

`HOT_PATH_REDESIGN_OPTIONS_20261009.md`末段写成：

```text
原生移动 → 发布索引 → 方向保护、困魔、安全区、环境保护
```

但stock实际顺序是：

```text
原生移动
→ 方向保护及必要的eight_way_collision_stop回退
→ _spatial_index_update()
→ 实际位移与计数
→ 困魔保护
→ 安全区保护
→ 环境保护定时门与查询
```

因此，**不能先发布一个尚未通过方向保护的位置，再执行方向回退**。即使随后会再次发布，也已经改变了原有可见状态和事务顺序。

### 2. 不能把环境查询提到移动之前

文档同一段的“provider batch call在engine movement之前”也不能直接照做。原环境保护在移动后、困魔和安全区没有提前返回、并且原环境定时门到期时才查询。

**可以提前取得已证明稳定的服务身份；不能提前执行原本移动后才发生的查询。** 也不能预先计算四个rollback布尔值，再一次性选择最终位置——前一个保护分支可能已经回退并返回，后面的查询原本根本不会执行。

所以我不采纳文档最后“再做一个preflight/postflight ABI_SHAM”的优先级。下一步应直接改实际查询实现，同时保留上述顺序，而不是再建立一层跨语言边界。

## 二、26.001ms差额已有计时范围解释，不必为它重跑

现在读到了SHAM诊断Enemy的完整计时入口：

```text
_quantum_diag_begin_callback()
→ locomotion初始化
→ _audio_observe_visual_state()
→ 原RuntimeDiagnostics.begin_timed_segment()
→ actor执行与视觉收尾
→ 原RuntimeDiagnostics.end_timed_segment()
→ _quantum_diag_end_callback()
```

因此，宏outer与原`enemy_physics_usec`**不是相同起止点**：宏outer还包含音频观察及原计时器外围工作。你给出的`R+P+B`比原Enemy统计大26.001ms，存在明确的代码层解释，不能因此直接判为嵌套重复记账；但我也没有把这26.001ms逐项归给其中某个函数。

这同时进一步限定了结论：

**当前R超过1028.63925ms，支持停止这个收益依据不足的切口；它不是对同一生产时钟下所有未来实现的严格下界证明。** 新SHAM报告已经保留了这个限制。

另一个需要沿用的精确定义：现有`reread_calls`记录的是三通道返回形状读取成功，**不是每次effect后完整重读world、target、life和provider身份的成本覆盖**。这些未来工作不能被算作已经包含在129.503ms内。

## 三、下一项具体改法：把“服务解析”和“数值查询”分开

建议候选名仍为 **`FORMAL_SPATIAL_READ_LANE`**。它不是新AI，不是新网格，也不新增持久化战斗状态库。

**原owner继续决定何时查询、移动、攻击；正式空间服务负责提供当前读段已经验证的数据，内部消费者不再层层恢复同一批事实。**

当前需要改变的结构是：

```text
多个owner/helper
  → 反复判断正式/legacy路径
  → 反复恢复provider、map、generation、revision、projection身份
  → 取得位置/半径/安全区数据
  → 执行很短的几何判断
```

改成：

```text
原逻辑首次确实需要该类查询
  → 取得当前读段的正式服务绑定
  → 多个内部消费者直接使用绑定和数值
  → 遇到相关写入或可重入调用，结束读段
```

**这里的“跨owner”指跨Enemy、GameRoot、WorldBackground和索引这几层接口，不是让多个actor共用一个旧帧快照。**

### 最低闭合范围

| 位置 | 本候选需要实际改变的内容 | 保持原owner负责的内容 |
|---|---|---|
| **GameRoot正式投影解析** | 增加内部正式绑定入口；读段内直接使用已解析profile中的转换，不每个点都重新恢复profile/identity | 正式地图资格、失败语义、切图和runtime失效 |
| **Enemy当前目标合法性** | `_retarget_internal()`当前目标检查、`_hc_target_usable()`和`_hc_access()`内部消费已取得的分类、身份及空间输入 | 观察、威胁、计时、目标释放、搜索节拍和动作许可 |
| **`_move_with_spatial_rules()`内部** | 方向保护、困魔/安全区/环境查询中的纯计算与投影，接入同一读通路；不再整段留给旧通用helper | 原生碰撞、回退setter、索引发布点、计数和返回顺序 |
| **近战候选消费** | 当前候选数值取得与精确循环衔接，避免输出Node后再次逐层恢复相同事实 | 原候选包络、成员完整性、顺序、实时资格和精确碰撞 |

**这四处是同一个候选的闭合要求，不是四个各自宣称有收益的小补丁。** 只在tick入口建一个context，后面照旧调用所有通用getter，不算完成。

### A. GameRoot：借用正式解析结果，不另造投影权威

当前`_resolve_projection_profile_for_map()`会构造key、取得runtime identity、比较缓存，再交付正式profile。即使命中缓存，这条路径也仍在执行。

建议新增一个私有入口，概念上类似：

```text
acquire_formal_spatial_binding(map_id)
```

它**调用现有正式解析器**，返回可供当前读段使用的真实profile身份和两向转换。内部多个投影直接消费它，不再重复经过完整解析器。

不要自行根据map ID或64×32常量构造“等价公式”。正式mapper返回的转换绑定了具体runtime；丢掉这层关系会把性能改动变成投影权威改动。

未知provider、Callable覆写、未正式发布的地图及无法确认对应关系的路径，仍用旧入口。这些fallback必须真实发生并计入成本。

### B. Retarget：移动当前合法性的计算，不移动其副作用

精确接入点是原观察/脏标记、稳定时间和威胁处理之后，当前目标的：

```text
valid → live → safe → disengaged
```

这些判断所需的空间事实可以用同一内部读通路取得；之后仍按原顺序释放目标、取消动作或进入搜索节拍门。

**不能先在host完整计算`live/safe/disengaged`，再把三个布尔值打包给native，随后把这部分称作已迁移。** 那只是传递答案，原热点仍然留在R。

同时，不保存依赖墙钟的最终`disengaged`答案，不延迟失效目标处理。当前源码是在搜索节拍门之前处理目标失效，顺序必须保持。

### C. Move：复用已知正式结果，但唯一位置writer不变

应给现有位置/索引提交链增加一个**内部的已知正式投影通路**，而不是另建位置writer。例如，移动后已经取得了对应当前真实screen位置的正式ground，索引发布内部可以消费这个结果，而不再回到通用投影入口重新证明一遍。

这个内部通路只接受当前读段证明对应的输入。任何方向回退、困魔回退、安全区回退、环境回退之后，之前的“当前位置”结果失效；历史起点仍作为历史值保存。

**仍保留原setter、原索引发布次数与发布位置，不延后到actor结束。** 这才是在减少重复解析，而不是把状态一致性工作省掉。

### D. 候选：避免“换一种容器后继续全量重读”

首版保留stock现有身份池及失效规则，只在当前同步查询段内取得必要数值，再执行身体、前排和终点判定。

不用另一组新数组把全部34怪再复制一次，也不为每个字段跨一次native。可使用调用方复用的typed scratch；关键不是容器名字，而是**已经取得的事实随后是否真的被直接消费**。

现有索引通路已经读取entry、Node和部分生命状态；通用形状查询还能够输出`position_ground_gu`。因此，适合改变的是内部结果与消费者的连接方式，不是再造一套候选检索系统。

有一个硬限制必须保留：**索引位置不是无条件可信的最新正式位置。** `update_actor()`会拒绝非有限坐标，entry可能保留上一次有限值。快路径必须证明该值仍对应当前实际位置及空间身份；证明失败走实时路径，不能拿陈旧位置替代原本的投影失败。

## 四、为什么这比再做provider包装更值得试

WorldBackground已经有`is_environment_actor_blocked()`，正式多边形路径会进入已编译snapshot；线段查询也能直接进入`poly_index.capsule_blocked()`。**并不存在“所有环境查询还完全没有批量/编译入口”的空白。**

因此，下一项不是“加一个batch API就会快”，而是：

**让正式路径的消费者直接使用当前已验证的服务与输入，减少重复分派、重复身份恢复和重复数据取得。**

这必须在provider侧和消费者侧同时成立。若只是新增一个typed方法，内部又完整调用原来的通用方法，收益范围依旧很小。

正式footprint、多边形、身体精确几何均不变。例如现有`actor_world()`逐点把屏幕footprint转换为ground，再做footprint判定；不能顺手换成一个圆或只检查中心。

## 五、50%的最低覆盖要求：必须按实际削减计算，不能按搬迁面积计算

用统一、可比的生产时钟定义：

- \(M\)：本候选实际覆盖、能够被加速的非重叠成本；
- \(s\)：这部分实际加速倍数；
- \(B\)：新增绑定、数据准备、刷新与写回的总成本。

则：

\[
\text{净节省}=M\left(1-\frac1s\right)-B
\]

要从107的2057.2785ms达到1028.63925ms，净节省必须至少1028.63925ms。

下面仅是规划算例，**不是从现有SHAM推导出的实测收益**：

| 假设实际加速 | 新增成本为0时，至少覆盖原总CPU | 新增成本为100ms时，至少覆盖 |
|---|---:|---:|
| 4倍 | 66.67% | 约73.15% |
| 5倍 | 62.50% | 约68.58% |

所以我不会把这次正式空间通路重构直接命名为“50%方案”。

**它首先要证明：除了几个getter自身耗时，还真正减少了多个owner内部的整条服务处理成本。** 若只减少分类、revision getter和部分缓存匹配，现有证据已经不足以支撑50%；无论写成GDScript还是C++，都不能改变这一点。

### 对下一候选的验收判断

正确性上，比较同输入纯查询的输出与原逻辑，原生移动、伤害、预算和索引效果只执行一次。性能上，额外影子比较关闭，原full诊断与完整outer保持开启；消失的纯helper调用应如实减少，不能为了对齐计数伪造执行。

若正式窗口轨迹再次不同，保留并标明，不把两臂差值解释成某个部件的纯成本。不存在通过挑选“攻击/HP相同”的窗口自动恢复严格因果归因的捷径。

**若上述四处闭合接入后仍只有几个百分点收益，就应结束“重复正式空间服务解析是主要可削减成本”的假设。** 不再追加更多context字段或native包装来延长这条路线；届时才能依据剩余实际成本决定是否迁移真正的数值循环，而不是预先承诺一个更大的quantum。
