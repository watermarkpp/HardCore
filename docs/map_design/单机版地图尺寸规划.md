# 单机版地图尺寸规划

任务编号：`MAP-SIZE-PLAN-2`  
依据：`地图尺寸修改方案.docx`  
状态：已数据化并接入 MSE 新建地图入口。

## 核心结论

原传奇客户端 MAP 尺寸只作为结构、动线和生态审计资料，不再直接成为单机地图的设计尺寸。MSE 使用 `godot_iso_64x32`，原图审计标记为 `mir2_48x32`，两套坐标必须显式转换。

所有地图同时保留：

- `source_size`：从二进制 MAP 头读取，永不被编辑器当作新建尺寸。
- `design_size`：面向单机探索节奏的实际施工尺寸。
- `map_type`：决定推荐尺寸上限和默认重构策略。
- `strategy`：说明缩编时保留竞技场、路线、功能或减少重复房间。

## 首批单机尺寸

- 比奇省 `256×256`，内嵌城镇 `64×64`，安全区 `48×48`。
- 盟重省 `280×280`。
- 沃玛森林 `180×180`；毒蛇山谷 `160×160`。
- 古墓三层依次 `120×120`、`112×112`、`96×96`。
- 沃玛寺庙入口至核心依次 `80×80`、`140×140`、`140×140`、`112×112`。
- 矿区样板 `160×160`、`140×140`；尸王殿 `96×96`。
- 祖玛三层 `160×160`、`150×150`、`140×140`；教主之家 `96×96`。
- 石墓阵单房间 `56×56`，保留 6–9 个有意义的关键房，不复制无意义重复房。
- 赤月魔穴、恶魔祭坛均 `112×112`。

## 运行原则

1. MSE 新建已登记地图时优先采用覆盖表；未登记地图采用类型模板。
2. 任何尺寸超过模板上限都必须由校验器报告。
3. 原图映射未确认的地图明确标为 `unresolved`，不得伪造来源文件名。
4. 旧运行地图暂不强制迁移；新地图由 Legacy Adapter 逐步替换，避免破坏当前可玩版本。
5. 编辑器源文件仍写入 `map_editor_workspace/`，构建产物才进入运行时资源目录。

## 文件职责

- `map_size_templates.json`：地图类型默认值、上限和策略。
- `map_scale_overrides.json`：首批 21 张地图的单机尺寸决策。
- `source_map_audit.json`：本地原 MAP 二进制头审计结果。
- `map_design_catalog.json`：供 MSE 和自动化脚本统一读取的合并目录。
- `audit_mir2_map_headers.py`：只扫描覆盖表声明过的源文件，避免全盘扫描卡死。
- `build_map_design_catalog.py`：确定性合并模板、覆盖和审计。
- `validate_map_design_catalog.py`：检查上限、坐标、Boss 房、迷宫房和来源状态。
