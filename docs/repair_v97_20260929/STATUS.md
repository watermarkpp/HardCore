## 已确认根因与实现

1. **锻造保存**：`EquipmentEnhancementRules.validate_enhancement` 对 `forge.stage` 与修饰数值只接受 GDScript `int`。JSON 读回为数值相同的 `float`，真实 W7 掉落装备进入存档校验后被拒绝。后台报告失败，安全退出也无法保存同一份数据；不是磁盘空间已满的证据。
   - 改为接受有限且无小数部分的 JSON 数字；仍拒绝字符串、布尔、小数、非有限值、超界等级、不匹配的强化历史和修饰数值。
   - 不更改强化概率、材料、费用、RNG、异步保存顺序或成功/失败玩法。
   - 原有 live 工作台测试使用普通实例，未覆盖带 `drop_instance_contract_id` 的存档校验。新增四类真实掉落实例，成功/失败后写盘、JSON 读回、再次取放及后续保存覆盖。
2. **出售图标**：商店商品卡直接使用纹理原始尺寸（碎片 521×856 等），遗漏了正式 `displaySize`。
   - 购买/出售共用卡片接入同一正式尺寸；自定义物品 UI 上限 32×32，地面上限 36×36，保持纵横比。旧原版物品保持原始像素尺寸。
   - 新测试在实际面板节点上检查 7 种圣物/徽章/碎片、11 种黑铁以及 2 个旧装备对照：出售、背包、仓库两侧、锻造、合成、装备栏和真实地面 Sprite2D。

## 失败分类与验证

- 图标新测试初次未投递商店报价响应，卡片尚未生成；补齐实际响应后，7 种新图标均在出售卡片复现原始大尺寸，其他入口保持正常。
- 修复后两项直接测试 PASS，runner 以退出码、错误日志及 marker 一起裁定；早期 FAIL 中的中途 marker 未作为通过。
