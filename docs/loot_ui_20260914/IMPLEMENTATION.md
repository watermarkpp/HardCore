## 实现和生产链

- **JP 判定**：`ItemDropInstanceRules.is_affixed_instance` 只将有效且含属性 modifiers 的装备判为 JP。旧 `drop_affix.applied`、生成概率和耐久随机结果保留，避免改变已有装备的校验结果；单独增加持久仍是有效装备，但不显示★、不按 JP 绕过过滤。
- **详情**：背包、仓库、商店公用 `ItemDetailDockedPresenter`。标题文字单行；★是单独 Label，名称本身居中。根据 Godot 实际排版测量选择宽高，去掉旧的纵横比高度下限；较长标题拓宽窗口后，正文按实际最宽行收紧并整体居中，各行仍左对齐。标题 20 / 正文 14，字号未增大。长正文保留只滚正文、无滚动条和属性帮助的关闭生命周期。
- **最终对齐规则**：用户最后明确“保持各行左对齐，以内容最长一行作为宽度，再让这个宽度居中”。名称以单独测得的正文名称宽度定位，★保持独立；属性正文按应用最终控件宽度后重新测量的最长行居中，排除防止换行所留的 1 像素。没有固定向右偏移。零、一至三位数、16 类长名称和各面板矩阵检查左右留白；中途误解为★合并居中或固定偏移的候选已撤回，不进入成品。
- **地面图标**：`LootPickup` 绝对 z=-2；地面/低层地表装饰仍在其下，人物及共用技能绘制平面在其上。名称独立绝对 z=1，图标不再因脚点 Y 排序遮挡人物或技能。
- **地面名称**：`LootPickupRuntimeManager` 在加入、移除、移动或切换过滤后合并一次延后布局；空闲帧无布局。`LootNameLayout` 按相邻空间桶分组，最多五件用一列，更多用两列，按登记顺序紧密排列并避开邻组名称。只移动 Label，拾取位置、空间索引和实例身份不变。
- **精确分类**：用户展示策略的 228–231、244–249 共 10 ID 改为沃玛；经原构建器生成名称表；过滤读取同一名称分类，阈值 2。其余名称色/描边不变，命运之刃 110 维持祖玛。
- **命运之刃**：新增显式用户权威 `drop.user_additions.v81`，只向怪物 76 追加 `dpv2.user.v81.m76.fate_blade`。引用炼狱 99 的 `dpv2.direct.m76.slot_029` 最终生效概率，再乘 2/3：当前炼狱 1/16，命运之刃 1/24。原 108 槽及原概率、优先级和 15 个上限保持不变；新槽继承引用槽优先级。冻结的掉落专用身份子集缺少 110，因此仅这个新增 ID 通过装备主目录精确解析，未修改旧子集或引入模糊名称回退。真实抽取、实例生成与背包接收均覆盖。
- **Buff 行**：人物技能和临时物品 Buff 记录首次生效时间，续时保留顺序；HUD 复用 26×26 图标，首项左侧对齐第一快捷物品格，原垂直高度不动。AC/MAC、魔法盾、隐身、治愈和神水共用一行；神水使用物品正式图标，到期收拢。
