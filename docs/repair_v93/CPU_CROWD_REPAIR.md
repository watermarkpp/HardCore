# 密集近战公共 CPU 查询整改（v92 之后，待统一打包）

## 范围和依据

施工基线 `3eb1cb8f4a80ba24d43cb0f07102b1f79763576d`，`codex/integration`；生产行为与 v92 APK 源码 `abbb5efbaba3b4d3f539f674b52b27ca2dc9f16e` 一致。用户批准基于现有手机记录先进行本地复现和施工，本轮不要求重新操作手机。

三份手机记录均为正式地图 913205（恐怖空间），v92、OpenGL、无资源覆盖补丁。两份 frame_only 的 P95 为 34.562 / 36.949 ms；详细计时模式明显增加观察开销，其帧率不能当作正常游戏帧率。详细记录中近战参战量上升与 CPU 开销同步上升；它没有 GPU 时间或连续温控证据，不能据此宣布所有卡顿都来自 CPU，或者把“大幅动画素材”认定为根因。

附件 Pro 报告作为待核验材料。核对后确认：直线推进、身体阻挡和多边形查询链存在可消除的重复工作；原有实现已经有按物理帧的静态查询缓存、100 ms 侧移重试和侧移候选批处理，不能重复添加这些机制。本轮没有引入活体碰撞缓存，也没有采用共享可变访问标记。

## 生产改动

1. `EnemyActor._hc_neighbor`：原来无论前方身体是否挡住，都先计算直线路段、失败边和落脚点。活体检查在原两个分支中本来都必需，因此把它移到前面；若身体挡住，这些不会被消费的静态结果直接短路。既有侧移节拍、路径分支、立即通行和最终移动碰撞仍保留；动态身体每次重新查询，延迟命中的新鲜检查不变。
2. `poly_index.gd`：构建时保存已扩展包围盒和多边形覆盖的首桶。查询只在“查询首桶与多边形首桶逐分量取最大值”确定的唯一公共桶处理该多边形。保持原候选顺序，取消查询去重字典；胶囊/身体足迹查询遇到精确命中即返回，不再先收集完整候选数组。索引在 setup 后仍然只读查询，可重入性不依赖共享 scratch 或访问计数器。
3. `poly_geometry.gd`：胶囊检查已经证明两条边不接触后，直接计算分离线段距离，不再在距离函数里重复做同一次接触判断。原浮点表达式、EPS、比较方式和四项最小值保留。

没有修改地图 authoring/runtime 数据、碰撞形状、刷新数量、怪物属性/掉率、攻击和移动节拍、人物/技能/宠物规则、动画素材、UI 或存档格式。没有更换包名、签名或主树版本配置。

## 测量方法

新增 `world_dense_melee_profile_test.tscn`，继承正式世界测试：真实加载发布地图、背景、玩家、全部正式刷新怪、空间索引、真实 AI/物理和正式技能入口。测试只调整合法初始位置及玩家生存条件：指定 10/20/30 只聚在同一合法区域，其余原怪保留并远离；恐怖空间总量 67，黑暗地带总量 62。固定种子、位置摘要、每种场景 3 次、每次 240 个 60 Hz 物理帧。有火墙组固定 8 片正式火墙，无火墙组为 0。

每份报告记录全部怪物存活/参战/休眠数量、位置、动作方向、实际伤害/移动诊断及源文件 SHA-256。比较脚本强制检查地图总量、实际参战量、火墙数量、位置摘要和采样长度一致。AI 原有真实时间重试时钟保留，因此不能要求两次运行的每个侧移时刻逐帧相同。

详细模式用于定位怪物与环境开销；轻量模式关闭详细诊断，仅用两个测试节点在物理回调前后取时间，测量物理回调阶段 CPU 耗时（包括同步移动/碰撞调用，不包含回调边界外的引擎工作）。headless 没有实际绘制，此处所有结果都是本地 CPU 证据，不是 Android 帧率验收。

初轮详细基线尚未加入这两个时钟节点，已从最终对照中移出并保留在 intermediate。最终详细基线使用相同探针重新执行；比较器强制所有非改动源码及两个测试脚本的哈希一致，基线三个生产文件必须与固定提交一致（允许仅 LF/CRLF 差异），候选三个生产文件在所有采样中也必须保持唯一哈希。

原始记录从 `outputs/repair_v92/world_v93_*.json` 收集；该目录名沿用旧测试的输出约定，不代表新记录属于 v92。最终证据复制到本目录的 `evidence/profiles/`，对照用 `tools/summarize_dense_melee_profile.py` 重算。

## 实测结果

7 组场景，每组基线/候选各 3 次，共 42 次有效采样。表中为 3 次结果的中位数，单位 ms/物理帧。怪物数量、地图数量、火墙数量、位置和采样长度全部通过比较器门禁。

| 场景 | 基线怪物 CPU | 优化后怪物 CPU | 降低 |
| --- | ---: | ---: | ---: |
| 恐怖空间 10 怪、8 火墙 | 1.814 | 1.622 | 10.59% |
| 恐怖空间 20 怪、8 火墙 | 5.035 | 4.150 | 17.57% |
| 恐怖空间 30 怪、8 火墙 | 8.641 | 6.889 | 20.28% |
| 恐怖空间 30 怪、无火墙 | 8.382 | 6.795 | 18.93% |
| 黑暗地带 30 怪、8 火墙 | 8.491 | 6.843 | 19.41% |

以上是详细诊断模式的怪物 CPU，不能与下面不同模式的总回调时间相减。轻量计时关闭了详细诊断：恐怖空间 30 怪整段物理回调平均值 8.067 → 6.504 ms（降低 19.37%），黑暗地带 7.943 → 6.472 ms（降低 18.51%）。对应 P95 分别 15.250 → 14.332 ms（6.02%）和 13.845 → 13.322 ms（3.78%）。尾部改善小于平均值改善，3 次短样本不构成长时间流畅或温控保证。轻量各次场景的攻击发起/结算均为 34/34，没有以减少攻击来换收益。

环境查询的累计 CPU 降低约 49%～50%。同进程、交替顺序的多边形微基准中，黑暗地带降低 17.71%，恐怖空间降低 19.86%。这些数字用于解释被消除的重复查询，不代表 Android FPS 同比例提升。

严格比较器曾拒绝早期轻量基线的文件字节摘要，未将其作为最终证据；随后用固定提交的精确 Git 文件字节重放基线，并在 finally 中恢复、校验候选字节，最终 42 份全部通过。初期 fixture 缺少 build hash、一个测试容器类型问题均已修复；旧生产代码对新增短路/不收集候选断言的 FAIL 是预期的回归复现。不存在以跳过断言获得的 PASS。

## 系统适用范围

实现没有怪物 ID、地图 ID、虫子名称或特定素材条件。`EnemyActor._terrain_neighbor_for_pursuit → _hc_neighbor` 是标准近战共用路径；其他 AI 保留自己的行为，但其共用的 `MonsterTerrainNavigationPolicy → poly_runtime → poly_index` 也获得多边形查询优化。`WorldBackground → poly_runtime.actor_world` 的环境身体足迹、导航图连边、路径平滑、编辑器/运行时共用几何同样消费该索引。不把近战的身体阻挡策略强加给投射物、法术或固定 Boss。

差分检查已遍历 release registry 的全部 **67 张发布地图**：两张重点图各 5000 组，其余每图 120 组，每组比较候选顺序、胶囊阻挡和身体足迹，合计 **53,400 次**，全部与冻结 v92 参考结果相同。既有怪物 AI 回归还包括非虫类、Boss、真实身体插入/死亡、绕墙、延迟攻击目标新鲜性及受击队列。推广在公共消费者上完成，无需为赤月、猪洞或其他怪物另加分支；具体性能收益仍随场景而变化。

## 怪物贴图动画审查

新增 opt-in `monster_animation_cpu_profile_test.tscn`：18 种正式怪物、虫子/赤月/其他三组，每组 30/60 个真实 EnemyActor + MonsterVisual，各 3 次 × 600 帧。关闭自动 actor 处理后手动调用正式 `MonsterVisual._process`，加载和测试状态准备在计时外；测试空闲、行走、攻击及受击 FIFO，并校验同帧不重复提交、同物种共享贴图和远距离释放。此处是热态公共更新函数的微基准，不包括世界 AI、协调器扫描或 GPU。

| 分组 | 30 只动画 CPU ms/帧 | 60 只动画 CPU ms/帧 |
| --- | ---: | ---: |
| 虫子（110/112/114/116/118/120） | 0.175 | 0.332 |
| 赤月（164/166/168/170/174/176） | 0.167 | 0.401 |
| 其他（18/24/50/62/128/138） | 0.166 | 0.369 |

虫子没有表现出异常的动画计算成本。每组 6 种怪物无论 30 还是 60 只都共用 30 张动作纹理；每 18,000 次动画调用仅约 2,800 次改变渲染状态。同帧重复提交与资源共用检查 PASS，270 个实例的远距离释放检查 PASS。公共 streaming 13 项回归、动作连续性、方向与受击队列通过。驻留缓冲区内的离屏实例仍会维护动作计时，完全释放资源的实例停止逐帧动画；直接冻结离屏计时可能破坏攻击/受击 FIFO，因此未随意增加降频。

只读像素审计还发现：虫子、赤月、其他三个六物种组的五动作图集解码 RGBA8 总量估算分别为 197.53 / 368.81 / 222.69 MiB，透明像素约 94%，跨全部方向和动作共同可裁的透明外边缘约 13%～32%。这不是实际 GPU 驻留测量，94% 透明也不等于能安全裁掉 94%；锚点、方向和极端帧都必须保留。该问题不是虫子特有。后续若针对显存/填充率优化，应在公共图集生成/绘制层做像素与锚点等价验证，并取得 GPU 证据。
